Building a personal archive that can outlive its tools

A website should be easy to change, but it should also remain understandable after the fashionable parts have moved on.

01

Design prototype copy. Final writing will be sourced from Markdown.

Anixir began as a small collection of experiments. The redesign treats it as something more durable: a record of engineering work, visual practice, and ideas in progress.

Own the source

The source of every article should remain a readable text file. Presentation can evolve around it, but the writing should never become trapped inside a database or proprietary editor.

Markdown gives the archive a modest and useful constraint. It keeps attention on hierarchy, links, images, and words: the pieces that matter after a redesign.

The website is an interface. The archive is the product.

Generate, inspect, publish

The publishing loop stays intentionally local: write, build, inspect the generated output, then push it. There is no invisible deployment machinery to debug and no runtime application to maintain.

npm run build
npm run preview
git push

Leave room for change

Durability does not require visual austerity. The site can animate, shift, and grow as long as its content remains portable and its output remains static.
